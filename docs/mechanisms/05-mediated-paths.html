Why this one is not a bug report

Nothing in panels 02 through 04 is a defect in Vörður. Every call that ran, ran correctly. The library cannot police a path it was never handed, and no amount of internal hardening changes that: it is a property of where the code sits, not of how well it works.

Which is why the assumptions are written down as assumptions. The threat model lists A-AS1 and A-AS2 with the consequence of each being false, and the README says production protection depends on mediating every relevant path. Those sentences are doing real work, and this strip exists because a reader tends to nod past them.

Mechanism only. process_inbound, check_tool_call, A-AS1, A-AS2 and T-IN13 are real, and panel 04 was measured rather than imagined: the same call, denied in one session and allowed in the other. Verified against Vörður 2.0.0, commit a0e51be. API names, policy fields and orderings can change too, not only numbers.
