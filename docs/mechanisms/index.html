The Mechanism Strips

Six short strips, one mechanism each. They exist because the hard part of this library is not any single check, it is that a decision late in a session can read something an earlier stage wrote down. That is difficult to say in a paragraph and easy to show across panels.

How they fit together

The strips

01

What the Guard Remembers

An instruction buried in a fetched page gets a fact written down. Two turns later a perfectly well-formed transfer is refused, because the gate can read that fact and four separate point tools cannot. The refusal needs a setting the library ships off.

session risk · contaminated_tool_policy · why the composition falls short

 02

A Marker Only the Model Sees

A token placed where only the model can read it, with a copy kept where the model cannot reach. If it ever appears on the way out, private context leaked, and no amount of re-casing, spacing or hyphenating hides it.

canary_token · canonicalized matching · escalation

 03

The Call That Came Back Changed

A user approved one action, in one conversation, at one moment. When the same call returns with the recipient changed and three turns elapsed, it is no longer the call that was approved.

args_hash · message_hash · ttl · change, not reuse

 04

What the Provider Sees Instead

Personal data the detectors recognize is replaced with tokens before the boundary, and at a default configuration a name is not among them. Coming back is not automatic either: two independent gates decide, both default to no.

deidentify · restore_policy · destination_policy

 05

The Path Around the Guard

Installed is not the same as in the way. One fetch that skips the library leaves no record, and a later call that was routed correctly then reads an empty ledger and allows what a hardened policy would have refused.

A-AS1 · A-AS2 · mediated paths · what the gateway fixes

 06

One Call, Two Questions

A tool call looks like one decision. It is two, asked of different things and sharing no code: an AWS key sails through the gate that authorized the send, and is stopped by the check that never knew which tool it was reading.

check_tool_call vs check_outbound · A-AS9 · every string leaf

Conventions, so you only learn them once

red
Something untrusted, something recorded against the session, a refusal, or a value that crossed unprotected. Red is never decorative.
green
Something the library retains or vouches for: a remembered marker, a token it issued, a check that passed.
numbering
Panels are numbered because the sequence carries the argument. Strip 01 panel 5 reads what panel 3 wrote; take the numbers away and the claim stops working.
codas
Every strip ends with what its mechanism does not do. A binding is not cryptographic, a canary prevents nothing, the vault cannot find what nothing looks for.
no numbers
No benchmark figures appear anywhere in the series, deliberately. Mechanisms stay true for years; measurements go stale and take the drawing with them.

Every API name, policy setting and field path in these strips is real and was read out of the source rather than recalled. Token values, email addresses and account numbers are invented for the drawings. Verified against Vörður 2.0.0, commit a0e51be. Names, policy fields and orderings change too, not only numbers, so the stamp is repeated on every page in the series. It is no longer the only guard on these claims: tests/test_mechanism_strips.py re-runs each one against the library and fails if either the library or the drawing moves without the other.
