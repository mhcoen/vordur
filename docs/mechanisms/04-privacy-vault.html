The honest edges

The tokens are pseudonyms, not redaction. Everything around a token crosses as written. A provider that sees the same stable placeholder beside “referral”, a clinic name and a date has most of what it needs, and the stability that lets the model reason about one person across a conversation is the same property that makes those mentions linkable. What the vault withholds is the identifier. It does not withhold the context, and it is not anonymization.

It cannot find what nothing looks for. Structural patterns and host-declared values are exact. A name or a street address with neither, and no registered detector, crosses in the clear. Be careful which signal you read for it. detection_incomplete is not the one: that flag is set when a registered detector reports its own coverage was partial, and a detector that was never registered reports nothing, so panel 01 comes back clean with the flag unset. The warning is the one. It names every configured class that has no structural pattern, no seeded value and no detector behind it, which at a default configuration is person and address.

The invariant is narrower than “only issued tokens resolve”. Because the body is error-correcting, strings within one symbol of an issued codeword also resolve, and those were never issued. What can be promised is that only exact codewords and that explicit radius resolve at all.

It protects the paths that go through it. Content sent to a provider without calling deidentify is not covered, in the same way the rest of the library governs the paths routed through it.

Mechanism only. deidentify, reidentify, prepare_tool_call, restore_policy and destination_policy are real. Token bodies and addresses are invented. No benchmark numbers appear, because numbers go stale and mechanisms do not. Verified against Vörður 2.0.0, commit a0e51be. API names, policy fields and orderings can change too, not only numbers.
