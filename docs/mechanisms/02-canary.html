A Marker Only the Model Sees

Put a unique marker where only the model can read it, and keep a copy somewhere the model cannot reach. If the marker ever turns up on the way out, you do not need to infer that private context leaked. You can see it.

What the canary does not do

It proves disclosure; it does not prevent a model from being persuaded. If private context never contains the marker, nothing is detected. If the host places the marker somewhere users or tools can read, it stops meaning anything, because then its presence no longer implies the model put it there.

The key has a placement problem of its own. Unless EPISODIC_CANARY_SECRET is set, the secret is a random value generated per process, so the marker minted by one worker is not the marker a different worker remembers. Egress there is checked against a token that was never placed, and the check does not fail: it passes, quietly, having compared against the wrong string. Set the variable in any deployment with more than one process, or with a process that restarts. The truncation is the other deployment fact worth knowing: sixteen hex characters is sixty-four bits of the tag’s two hundred fifty-six, a deliberate trade rather than an accident of formatting.

It is also narrow by design. It catches the exact string leaving, not a paraphrase of the instructions around it. Overlap and provenance checks cover that ground, which is why the canary runs first and they still run at all.

And the joined-field scan in panel 04 narrows a gap rather than closing it. Values are joined in traversal order, so a caller that controls field order can keep the halves apart, and nothing per-call reassembles a token sent one half per request. Both limits are pinned rather than assumed, by tests/gateway/test_gateway.py::test_reordered_fields_remain_a_known_gap, whose docstring says in as many words that the gap is visible rather than closed.

Mechanism only. Every name here is a real call or setting: canary_token, detect_canary, escalated_tool_policy. The token shown is invented for the drawing. No benchmark numbers appear, because numbers go stale and mechanisms do not. Verified against Vörður 2.0.0, commit a0e51be. API names, policy fields and orderings can change too, not only numbers.
